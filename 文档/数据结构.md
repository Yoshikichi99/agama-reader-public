## 二、正文层格式

```jsonc
[
  {
    "p": "SA/SA1152",          // 页面 id
    "c": "SA",                 // 部（栏目代码）
    "k": "SA.1152",            // 本条的经号（页面可能含多经，故按经存）
    "h": {                     // 结构头，没有结构标签则缺省
      "nm": "雜阿含1152經",     // 经名
      "alt": ["正聞本1251經", "佛光本1135經"],
      "path": "婆羅門相應/八眾誦/祇夜",   // 品·相应路径，建目录树用
      "tr": "莊春江標點",
      "refs": ["AA.2.1"]        // 经末的异本对号
    },
    "b": [                     // 块（一个 <br> 一块）
      {
        "i": 1,                // 块序号（1 起），**这就是地址**
        "t": "如是我聞：",      // 纯文本，可搜索可高亮
        "fp": "a1b2c3d4",      // 块指纹（sha1 前 8 位）
        "g": "p",              // 显示提示：p 段 / v 偈 / num 编号行 / h 小标题
        "m": [                 // 注标（仅本块有注时出现）
          { "o": 0, "k": "n", "r": "1", "n": 4 }
        ]
      }
    ]
  }
]
```

### 2.1 地址规则（重要）

**注释锚点 = `页面 id` + `块序号 i` + `块内字符偏移 o`**，例：`SA/SA1152|1|0`。

三者之外再加 `fp` 做二次身份：清洗器升级导致块序号漂移时，用指纹把注释重新挂回去。

### 2.2 `g` 只是显示提示，不是地基

原文用全角空格缩进区分偈与段，但**各集不一致**（法句 2 格、長老偈 1 格、雜阿含偈 2→3 格），
靠缩进分类并不可靠。所以：

- `g` 只用于排版（偈体收紧行距、不挂段号）；
- 判错不影响锚点，改判也不必重跑注释包；
- 偈体集（法句/長老偈/經集/本生/譬喻/佛種姓/所行藏/天宮事/餓鬼事/如是語/優陀那/小誦）
  整集直接标 `v`；其余部在首版一律 `p`，**不做猜测**。

## 三、注释层格式

```jsonc
{
  "v": 1,
  "meta": { "id": "zcj", "name": "莊春江註解", "author": "莊春江",
            "license": "CC BY-NC-SA 4.0", "cleanver": "1.0.0", ... },
  "glossary": { "1": "「如是我聞」…", ... },       // 999 条词条
  "entries": [
    { "p": "SA/SA1152", "k": "cmp", "h": "（漢巴經文比對）…" },   // 经级题头
    { "p": "SA/SA1152", "k": "note", "r": "1", "h": "「賓耆迦」…" } // 页内注
  ]
}
```

解析规则：

| 注标 | 到哪里找 |
|---|---|
| `m.k == "n"`（词条注） | `glossary[m.r]` |
| `m.k == "l"`（页内注） | `entries` 里 `p == 本页 && k == "note" && r == m.r` |

**叠加多套注释**时，同一个注标会在多个包里各找一次，找到几条就显示几条，按 `meta.name` 分组。

## 六、巴利层

`数据\clean\pali.json.gz`，3.52 MB。原数据是 6,141 个**内容哈希去重的裸块**，
与目录毫无归属关系；现已挂成三层索引。

```jsonc
{
  "blocks": { "哈希": "巴利文……" },       // 6,115 块（去掉 26 条重复的来源题头）
  "decl":   { "哈希": "SN.16.5" },        // 4,421 块自带经号（巴利的「自我介绍」）
  "page":   { "SA/SA1141.htm": ["哈希…"] },  // 页面 → 块
  "key":    { … }                          // 仅当与 page 不同才存（实际只剩 3 条）
}
```

取法：`key[k]` 优先，没有就 `page[leaf.p]`。

### 6.1 一条必须说清的语义

**汉译经页面挂的巴利，往往是对读本的巴利，不是本经的巴利。**

| 汉译经 | 所在页 | 巴利自称 |
|---|---|---|
| 雜阿含1141 | `SA/SA1141.htm` | **SN.16.5** |
| 中阿含98（念處經） | `MA/MA098.htm` | **MN.10** |
| 雜阿含1 | `SA/SA0001.htm` | SN.22.12 / 22.13 / 22.14 / 22.51（4 块） |

所以界面不能把这段巴利标成「雜阿含1141的巴利文」，得按 `decl` 显示它的真实经号
（「巴利：相應部16相應5經」）。`decl` 字段就是为此存在——没有它，这一层根本说不清来源。

### 6.2 覆盖

| 部 | 条目 | 有巴利 | 占比 |
|---|---|---|---|
| 相應部 / 中部 / 長部 / 增支部 | 1806 / 152 / 34 / 1767 | 全部或 99.8% | 100% |
| 小部 16 集 | 1,724 | 1,724 | 100% |
| 長阿含 | 30 | 27 | 90% |
| 中阿含 | 222 | 192 | 86.5% |
| 雜阿含 | 1356 | 936 | 69% |
| 增壹阿含 | 473 | 224 | 47.4% |
| **別譯雜阿含** | 362 | **0** | **0%** |
| 合计 | 7,564 | 6,504 | **86.0%** |

低的是**汉译部本身没有对读巴利**，不是挂接失败；別譯雜阿含的键里也没有对号，
所以连对读本都指不出来。

### 6.3 「巴利語原文」入口因此成立

南传各部 + 小部做到 100%，意味着「按目录树用巴利视图读」这条路是通的：

### 6.4 巴利逐段直译（相应部，2026-11-15 接入）

`数据\clean\pali.zh.json.gz`，1.10 MB。来源 `数据\trans_src\pali\sn-self-export-1114.tgz`
（每经一个 JSON，`pali[]` 与 `self[]` 逐段对齐）。

> 直译为 **AI 批量初译**，由 **昭 同修** 提供，未经逐句人工校对，**不保证准确**，仅供参考；
> 如有同修愿意提供更可靠的对译本，欢迎通过授权页联系。翻译包同以 CC BY-NC-SA 4.0 约束。

```jsonc
{ "v": 2,
  "meta": { "id": "sn-self", "name": "巴利逐段直译（相应部）", "format": "pairs", ... },
  "byKey": {
    "SN.1.1": [ { "p": "巴利段", "z": "中文段" }, ... ]
  } }
```

**对齐方法（v2）**：不再把译文往 `pali.json.gz` 的块行上硬挂，而是**直接采用译者的段落对**。
源包 `pali[]`/`self[]` 段数不一致时：

- 中文多 1 段 → 合并最短的相邻两段；
- 巴利多 1 段 → 在最长中文段的逗号/分号处拆一段；
- 差 2 段以上 → 只保留巴利段、中文留空（不硬配）。

**建表结果（2026-11-15 v2）**：

| 项 | 数值 |
|---|---|
| 源文件 | 1806 经（SN 全部） |
| 落到正文 | 1806 经 / 7727 段 |
| 原样对齐 | 1750 经 |
| 合并中文 | 33 经 |
| 拆分中文 | 20 经 |
| 不硬配（只留巴利） | **3 经**：SN.18.10、SN.49.13-22、SN.50.13-24（名单 `pali.zh.mismatch.txt`） |

这样原来 B2 的 114 段“行匹配不上”直接消失；B1 的 56 经里 53 经被救回，
只剩 3 经无译文。界面按源包段落显示，长段再做句级成对。

**前端**：`core.js` 的 `ensurePali()` 一并加载本表，`paliFor()` 返回 `pairs`；
有译者段落对的经直接用 `pairs`，没有的（AN/MN/DN/小部）退回 `pali.json.gz` 的块行。
北传页的巴利块是 SN 对读本（如 SA.1 → SN.22.12…），`paliFor()` 会按 `decl`
逐个合并对读本的直译，不再只查本经号。
`app.js` 在每段巴利下渲染 `.pz`，由「翻譯 → 顯示巴利直譯」开关（`body.no-palizh`）控制。
≥160 字符的长段按句切成 `.plp`（一句巴利 + 一句中文），句数差 2 以上退回整段。

**用户覆盖**：导入的巴利直译存 `localStorage['ar.palizh']`（`{ 经号: { 规范行: 中文 } }`），
`paliFor()` 在内置段落对上合并；「我的資料」备份包含这一层。
重跑：`python 工具\挂巴利译文.py` → `python 工具\拆包.py`。



## 七、对读表

`数据\clean\xref.json.gz`，0.03 MB。三个独立来源合并成一张**双向图**：

| 来源码 | 含义 | 边数 |
|---|---|---|
| `r` | 经末对号（`[MA.98, AA.12.1]`） | 1,638 |
| `p` | 同页对读（原站把几部经排在同一页） | 2,217 |
| `d` | 巴利块自称的经号（汉译页尤其重要） | 1,662 |

```jsonc
{
  "edges": { "MN.10": [ {"k":"MA.98","s":"dpr"}, {"k":"AA.12.1","s":"dpr"} ] },
  "groups":    [ ["AA.2.1","AN.1.296"], … ],   // 异译组，2–12 员
  "groups_big":[ … ]                            // 疑似多经共对读（4 个，17–35 员）
}
```

### 7.1 两个必须分开的概念

| 概念 | 是什么 | 用哪些边 |
|---|---|---|
| **异译组** | 同一部经的不同译本（MN.10 ↔ MA.98 ↔ AA.12.1） | 只用 `r` + `d` |
| **同页群** | 一个对读跨页上并列的所有经，可达几十部 | `p` |

用 `p` 建组会连成大团——实测有 35 员的团，那是排版产物不是异译关系。
所以 `groups` 只由 `r`+`d` 建，`groups_big` 把这 4 个大团单列，标为「疑似多经共对读」。

### 7.2 区间经不参与传递

`SN.56.105.107` 一页涵盖 105–107 三经。它**可以连边，但不许向外扩**，
否则一个区间经就能把整个相應串成一团。判定：键的数值段 ≥ 3 段即视为区间经。

### 7.3 结果

- 有对读的经 **3,283 / 7,564（43.4%）**；
- 异译组 **1,156 个**，920 个是 2 员（一对一对应），最大的 9 员；
- 组的两部组合前几名：`SA+SN` 650、`AN+SA` 113、`AA+AN` 84、`MA+MN` 70。

剩下 56% 没有对读的，主要是小部（1,724 条）与未收对读的汉译经——**本来就没有对应本**，
不是没建好。

## 八、主题索引

`数据\clean\theme.json.gz`，0.02 MB。**不是人工列表，是让数据自己说**：
把每个「相應 / 品 / 集」当节点，统计两节点之间有多少对读边，双向都是最强的才认定同一主题。

```jsonc
{
  "groups": [ { "s":"SA", "n":"陰相應", "p":"五陰誦", "k":["SA.1", …] }, … ],  // 208 个
  "themes": [ { "n":"陰相應／蘊相應", "w":89, "r":0.82, "t":"SA-SN", "g":[0,57] }, … ]
}
```

只做四组平行系统的配对：雜阿含↔相應部、中阿含↔中部、長阿含↔長部、增壹阿含↔增支部。

### 8.1 三条判据，缺一个就出噪声

| 判据 | 值 | 拦住了什么 |
|---|---|---|
| 绝对边数 | ≥ 5 | 偶然三两条对读不足以立主题 |
| 相对强度 | 边数 ÷ 较小一方经数 ≥ 0.2 | 大面积「弱相关」被误当主题 |
| 双方经数 | 各 ≥ 3 | **1 经的小相應会把强度抬到虚高**（`天相應／雲相應` 强度 5.0 的假匹配） |

另外只保留「互为最强」的配对，一方被多方争抢时取最强的那个。

### 8.2 结果：47 个主题

最强的几个，和学界公认的对应完全一致：
